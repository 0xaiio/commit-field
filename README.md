# 耕年 · CommitField

> 一面可以环绕、可以编辑、可以「播下」的立体 Commit 墙。

**仓库**：<https://github.com/0xaiio/commit-field> · **许可**：MIT · **依赖**：零 · **形态**：可直接打开的单文件 HTML

---

## 1. 项目简介

CommitField（《耕年》）把 GitHub 贡献日历的 53 × 7 网格升成一片可环绕的立体田：每一天不再是一个色块，而是**一根从地里长出来的柱子**——柱高按当日贡献数的平方根连续编码并限幅，柱顶颜色仍保留五档分档色阶。俯瞰时它读起来仍是原来的 commit 墙，绕到侧面则变成有高低、有遮挡、有投影、有孤峰的田垄。

仓库收录两个可独立运行的版本：

- `耕年-CommitField-3D.html`：**主作品**。纯 Canvas 2D 手写透视相机（look-at 投影 + 画家算法 + 背面剔除 + 方向光），无任何外部脚本、字体、图片或网络资源加载依赖，可离线打开。
- `耕年-CommitField.html`：**2D 对照版**。同一份数据的平面翻面版本，格子按列波浪式 3D 翻转成耕作面。

另外两份 HTML 是随项目迁移的**改造前历史快照**（五阶段演进前、自定义账号功能前），保留用于对照，不是运行时依赖。

默认展示内嵌的 `github.com/hengxin` 真实贡献日历快照：`2025-11-02 → 2026-11-06`，共 **370 天**（末列 6 格）、**2,978 次贡献**、**247 个活跃天**、最长连续 **37 天**、单日峰值 **163 次**（2026-06-25）。页面所有统计均由数据实时计算，不写死展示值。

> **数据口径**：GitHub 的 `contributions` 含提交、PR、issue 与 review，**不等于纯 commit 数**；「四幕」按 53 周均分，是叙事分段，不是自然季节。

## 2. 功能特性

### 2.1 数据

| 能力 | 说明 |
| --- | --- |
| 默认真实数据 | 内嵌 `github.com/hengxin` 快照，离线可用；真实模式使用 GitHub 原生五档分档，图例按当前数据动态生成区间 |
| 自定义账号 | 输入 GitHub 用户名或个人用户页链接（如 `https://github.com/hengxin`），实时获取该账号的贡献日历 |
| 演示数据 | 确定性生成的 371 天数据集（`2025-11-02 → 2026-11-07`），注入连续活跃段、休耕期与四个高峰，非真实仓库历史 |
| 统计卡 | 全年贡献总数、活跃天、最长连续、长休耕段数、单日峰值，随编辑与切换实时重算 |
| 数据切换 | 控制条「演示 / GitHub 真实」，以及「返回默认」「↻ 刷新」，来源行与页脚同步标注当前账号、时间与口径 |

自定义账号链路：先用 `api.github.com/users/hengxin` 这类用户查询接口（路径末段替换为目标用户名）校验账号存在性，再依次尝试三个公开通道获取日历（主通道 `github-contributions-api.jogruber.de/v4/hengxin?y=last`、备用通道 `github-contributions-api.deno.dev/hengxin.json`、末位回退 `github.com/users/hengxin/contributions` 的 HTML 解析），按日期排序、去重、对齐周日起始、重算分档区间，统一规范化为与内嵌数据完全相同的结构（`dates / counts / levels / bounds / from / to`）。因此渲染层、统计层与命中检测无需区分数据来源。

错误状态覆盖：链接格式错误、非 `github.com` 链接、非个人用户页、含空格输入、空输入、用户不存在、组织账号、API 限流、无贡献记录、全部通道失败。**任何错误都不改动当前展示的数据**，且加载按钮保持可重试。

### 2.2 3D 渲染与镜头

- 手写标准透视 look-at 相机，`FOCAL = 2200` 长焦；柱体按深度从远到近绘制并做背面剔除，方向光决定侧面明暗，高柱在地面留下投影，平视时叠加地平线辉光与暗角。
- 四种视角：**俯瞰**（读原 53 × 7 墙）／**等距**（读田垄高低与纵深）／**平视**（读贡献天际线）／**自由**（拖拽），视角间相机缓动飞行，不瞬切；可开自动巡游。
- 「摊平 ↔ 立起」让全部柱子连续升降，是从平面记录面长成立体田的转场，不另做一套图形。
- 悬停显示当日精确数值，点击柱子展开详情；命中检测在投影后的多边形上完成。

### 2.3 信息编码

| 信息 | 视觉编码 |
| --- | --- |
| 提交频率 | 五档色阶 + 柱高（双通道）；摊平后仍保留原色阶 |
| 连续记录 | 金色田埂折线，只连接 **≥12 天** 的连续段 |
| 空白期 | 贴地半透明雾层与低洼地，只标注 **≥10 天** 的休耕段；短连续与短空白交给相邻格子本身表达，避免线条盖住数据 |
| 活跃周期 | 四幕（开荒／萌发／盛长／收成与休耕）随扫描线切换背景色温、强调色与生长节奏（每列 150 / 105 / 62 / 110 ms） |
| 峰值日 | 孤峰光柱、径向光晕与数值标注；该标记由数据自身产生，不是额外装饰 |

### 2.4 无人机巡航

一架农用播种无人机沿 W1 → W53 掠过田垄，**把 commits 逐列「播下」**：复用 `growth[]`（某天的柱子是否已长出），有贡献的格子置 1 并投放光点，休耕地跳过；金色田埂只画已播下的段，随播种逐段接上。

- 状态机：`idle → takeoff → seeding → completed / recalled / aborted`，另有 `paused`；结束/召回后机体淡出，**已播下的 commits 一律保留**。
- 节奏：每列时长 = 所属四幕 `pace × 1.6`（约 99–240 ms），7 行之间 S 形摆动，高度跟随当列最高柱顶，全程约 10 秒。
- 触发与结束：控制条「◈ 起飞巡航」或 `D` 键；再点一次召回（不叠开第二条航线）；到 W53 自动完成；播放、时间轴、四幕跳转接管时安全中断；页面切后台自动暂停、回来继续。
- 任务接口：`MISSIONS` 注册表提供**播种 / 巡检 / 收割**三种任务，切换任务不改变状态机。
- 反馈：四轴机体、旋翼、柔光晕、下投光束、地面阴影、渐隐尾迹、柱顶脉冲涟漪，以及显示当前周／进度／播下数／跳过数／孤峰状态的状态卡。
- 边界：空数据拒绝启动、重复触发防重入、单帧步长上限防切后台瞬间跑完、`try/catch` 异常兜底召回、末列不足 7 格不越界。

### 2.5 进阶能力

- **反事实时间轴**：编辑模式下点柱切换该日 `0 ↔ 原值`，虚线幽灵柱标出原值，实时重算统计、最长连续、休耕、四幕曲线与孤峰，并显示 Δ 徽标；「↺ 还原」恢复。
- **60 秒自叙事纪录片**：按当前数据的戏剧性自动编排 7 段共 60,000 ms 镜头（开荒 → 最长连续 → 最长空白 → 孤峰 → 最强幕 → 换形态 → 收成），含字幕、运镜、时间轴与形态联动。
- **形态语法切换**：柱阵／梯田／织物／年轮四种世界观，`FORMS` 注册表提供 `coord + draw`，共享同一相机、统计、巡航与命中检测，各配推荐俯角；年轮形态下田埂改为沿圆周细分的短弧刻痕。
- **生成式生态**：连续段藤蔓、休耕地草、孤峰分形树、四幕叶色；「▣ 数据视图」一键回到柱阵 + 等距 + 关闭生态。
- **导出**：2× 分辨率年度海报 PNG（含标题、五项统计、形态/视角与来源水印）；纪录片可用 `MediaRecorder` + `canvas.captureStream(30)` 导出 WebM，环境不支持时静默降级为海报。

### 2.6 交互与响应式

- 键位：`←` `→` 移周、`空格` 播放、`1` `2` `3` 切视角、`R` 回等距、`D` 起飞巡航、`E` 编辑年份、`P` 导出海报、`Enter` 加载账号。
- 拖拽旋转、滚轮推拉、悬停 tooltip、点击聚焦；播放／暂停、时间轴拖动、四幕跳转、田埂显隐。
- CSS 断点 `980px` / `600px`，Canvas 随容器重算，窄屏控制条换行、主体仍可见。

## 4. 安装与使用

```bash
git clone https://github.com/0xaiio/commit-field.git
cd commit-field
```

**无需 `npm install`**，也没有构建步骤。任选其一打开：

1. 直接双击 `耕年-CommitField-3D.html`（`file://` 即可运行）。
2. 若希望以 HTTP 方式访问（例如想让 `localStorage` 与本地预览面板共享同一 origin）：

   ```bash
   python -m http.server 8000
   # 浏览器打开 http://localhost:8000/耕年-CommitField-3D.html
   ```

常用入口：

| 目的 | 操作 |
| --- | --- |
| 打开 2D 翻面对照版 | 打开 `耕年-CommitField.html` |
| 打开演示数据 | 在 3D 版地址后加 `#demo`；无 hash 或 `#real` 为真实数据 |
| 加载他人账号 | 账号栏输入用户名或 `https://github.com/用户名` → 「加载账号」；用「返回默认」「↻ 刷新」切换 |
| 完整体验主线 | ▶ 从年初生长 → ◈ 起飞巡航 → 切「平视」看天际线 → 拖拽绕田 → ▥ 摊平为记录面 |

建议的首次探索顺序：先点「▶ 从年初生长」，再点「◈ 起飞巡航」观察左右两半田的对比；随后依次切四种形态、开启「❀ 生态层」，并随时用「▣ 数据视图」退回数据基线；最后用「✎ 编辑年份」抹掉任意一天，观察统计卡与田埂如何同步变化。

## 6. 配置项

本项目**没有外部配置文件、环境变量或 API Key**。可调内容集中在两处：URL 参数、浏览器本地存储，以及 HTML 内 `<script>` 顶部的常量。

| 位置 | 名称 | 作用 / 当前值 |
| --- | --- | --- |
| URL hash | `#demo` | 以确定性演示数据集打开；其它值（含 `#real` 或无 hash）使用真实数据 |
| `localStorage` | `cf_account_state` | 当前数据源状态（`default` 或 `custom` + 用户名），跨刷新保持 |
| `localStorage` | `cf_cal_` + 用户名 | 该账号规范化后的贡献日历缓存 |
| `localStorage` | `cf_notice` | 重载前暂存的加载结果提示，消费后删除 |
| JS 常量 | `DEFAULT_REAL` | 内嵌的 `github.com/hengxin` 日历快照（370 天，2,978 次） |
| JS 常量 | `ACTS` | 四幕名称、配色与 `pace`（150 / 105 / 62 / 110 ms） |
| JS 常量 | `LEVELS` / `LEVEL_RGB` | 五档色阶；真实模式图例按 `bounds` 动态生成 |
| JS 常量 | `FOCAL` / `VIEWS` / `FORM_VIEW` | 相机焦距 `2200`、四视角方位/俯角/距离、各形态推荐俯角 |
| JS 常量 | `FORMS` / `MISSIONS` | 形态注册表（柱阵/梯田/织物/年轮）与任务接口（播种/巡检/收割） |
| JS 常量 | `DRONE` | `ALT 36`、`COL_SCALE 1.6`、`TAKEOFF 900ms`、`TRAIL 28`、`PULSE 760ms`、`DROP_MS 430ms`、`MAX_DT 60ms`、`SWAY 2.1` |
| JS 阈值 | 连续段 / 休耕段 | `≥12 天` 画田埂，`≥10 天` 画休耕雾 |
| CSS | 响应式断点 | `980px` / `600px` |
| 外部服务 | `api.github.com/users/hengxin` | 账号存在性校验（公开、未认证） |
| 外部服务 | `github-contributions-api.jogruber.de/v4/hengxin?y=last` | 主日历通道（JSON，带 CORS） |
| 外部服务 | `github-contributions-api.deno.dev/hengxin.json` | 备用日历通道（JSON） |
| 外部服务 | `github.com/users/hengxin/contributions` | 末位回退（HTML 解析 `td[data-date]` 与 `tool-tip`） |

表中外部服务以默认账号 `hengxin` 举例，实际请求会把路径中的用户名替换为账号输入值。所有网络请求均为公开的未认证 GET；页面不保存也不要求任何凭据。

## 7. 数据说明

- 默认快照的分档区间为 `0 / 1–17 / 18–34 / 39–49 / 54–163`（GitHub 原生分档，按该账号数据重算）；自定义账号会按其自身分档重建图例。
- 四幕按 53 周均分，用于叙事节奏，**不是**自然季节或 GitHub 官方统计口径。
- 柱高使用 `min(145, 6 + sqrt(count) × 9.5)` 的连续编码并限幅，避免单日高峰遮住整片田；柱顶颜色仍是分档色阶。立体化是**数据可视化编码**，不是对任何模型或服务的内部机制复现。
- 演示数据集为确定性生成，用于检验视觉隐喻在非规则分布下是否成立，不代表任何真实仓库。

## 8. 开发、构建与测试

**构建**：无。项目没有打包器、编译步骤、依赖安装或产物目录；修改即直接编辑对应 HTML 内的 `<style>` 与 `<script>`。请保持「单文件、零外部依赖、可离线打开」这一约束。

**测试**：仓库**未**随附自动化测试框架、测试用例或 CI 配置。开发期曾使用无头 Chromium/Edge 通过 CDP 执行交互断言与截图目视复核，覆盖双数据源、三视角与自由拖拽、Canvas 命中、巡航状态机全部边界（重复触发、召回、暂停恢复、互斥中断、空数据、异常注入）、反事实重算、四形态、纪录片与录制降级、海报导出、390px 窄屏与控制台报错；这些验证脚本是开发期的临时文件，**不在本仓库中**，因此不能在此复现运行。

建议在浏览器里执行的手动回归清单（与页面实际控件一一对应）：

1. 打开主页面，确认 5 张统计卡显示 `2,978 / 247 / 37 天 / 2 段 / 163 次`，来源行标注默认账号与抓取日期。
2. 切「演示」或加 `#demo`，确认演示数据 371 天与动态图例变化。
3. 依次点「俯瞰 / 等距 / 平视」，拖拽旋转、滚轮推拉，悬停与点击柱子查看详情。
4. 点「◈ 起飞巡航」跑到完成，确认状态卡播下 247 枚、跳过 123 块休耕地、孤峰点亮；中途再点一次可召回。
5. 点「✎ 编辑年份」并点击一根有贡献的柱子，确认统计 Δ、虚线幽灵柱与田埂同步变化；「↺ 还原」恢复。
6. 依次切四种形态，确认悬停/点击仍生效；开「❀ 生态层」后用「▣ 数据视图」一键退回。
7. 点「▣ 年度海报」下载 PNG；点「▶ 60s 纪录片」确认 7 段字幕，「● 录制」在支持的浏览器中导出 WebM。
8. 输入无效链接、不存在的用户名，确认明确的错误提示且当前数据不变；输入真实用户名确认统计与来源行更新。
9. 把窗口缩到 390px，确认控制条换行、Canvas 重算、无横向溢出。

提交前建议：

```bash
git config core.autocrlf false        # 源文件为 CRLF，避免整文件换行被改写造成巨大 diff
git config core.whitespace cr-at-eol  # 让 diff --check 不把 CRLF 行尾误报为尾随空格
git diff --check
```

## 9. 已知限制

- 自定义账号依赖第三方公开贡献日历服务与 `api.github.com`；未认证调用受 GitHub 每小时限额约束（60 次/小时），接口限流或全部通道不可用时页面会保留当前数据并给出明确提示。
- `localStorage` 按浏览器 origin 隔离：以 `file://` 直接打开与通过 `http://localhost` 预览时的账号状态不共享，状态栏会显示当前实际来源。
- 年度海报的页脚来源文案固定写默认账号信息，自定义账号下不会随之更新；导出文件由浏览器下载，不纳入版本控制。
- WebM 录制依赖 `MediaRecorder`；不支持的环境自动降级为海报，不弹窗阻塞。
- 仓库不含自动化测试脚本，回归依赖上一节的手动清单。

- 从 `main` 建立分支，提交信息说明改动动机与影响范围；提交前请按第 8 节清单在浏览器中回归。
- 保持单文件、零外部依赖、可离线运行的约束；不要引入需要构建步骤或包管理器的改动。
- 不要提交个人数据、凭据、浏览器下载产物或本地编辑器配置；不要改动 `.gitignore` 中已排除的类别。
- 若改动沿用内嵌真实数据，请在说明中注明数据来源与时间口径。
