## 一、这支片子的定位

《耕年》把一个 GitHub 贡献日历的 53 × 7 网格，做成一片可以环绕、可以编辑、可以「播下」的立体田。本片面向三类观众：想看演示效果的开发者、关心交互体验的设计者、以及想了解一次真实长程协作如何落地的人。

因此全片按四段推进：**冷开场看效果 → 创作过程看取舍 → 项目成果看演示 → 收尾看使用体验与获取方式**。

**表达纪律（重要）**：本片只陈述可复核的事实与可追溯的工作判断。

- 不出现模型参数、评测成绩、性能对比或「行业首个」一类无法从本项目复核的说法。
- 不编造作者的个人情绪、使用时长、团队规模或用户反馈。
- 涉及「使用 Hy4 的感受」的段落，只写本次会话里能被工作记录支撑的**工作方式与结果判断**；模型标识需由作者在客户端确认后再对外发布。
- 所有数字来自页面实时计算、源码常量或开发期验证记录，见文末「事实依据」。

## 二、旁白正文

> 编号 N01–N26 与《视频脚本》《分镜表》《字幕文件》逐一对应；字幕即旁白原文，不做改写。
> 数字一律写成中文读法，确保配音与字幕完全一致。

N01｜这是一面熟悉的 GitHub 贡献墙：五十三列、七行，颜色越深，那天贡献越多。

N02｜在《耕年》里，每个格子都会从地里长出来：贡献越多，柱子越高。

N03｜俯瞰还是那面墙；绕到侧面，它变成有高低、有阴影、有孤峰的田。

N04｜只讲能复核的事：怎么做出来的，现在能做什么，以及这轮在 WorkBuddy 里用 Hy4 协作留下了什么。

N05｜起点很朴素：让 commit 墙有叙事感，但不能盖住数据。

N06｜第一版把三百七十一个格子做成可翻面的田：正面色阶，背面作物；连续记录连成金色田埂，空白期起雾。

N07｜接着换成真实贡献日历：三百七十天、两千九百七十八次贡献、二百四十七个活跃天，逐日求和与主页自报完全一致。

N08｜真实数据立刻检验出两个问题：写死的分档让活跃天挤进最深色，作物高度因一个无效单位一直是零。

N09｜改用 GitHub 原生五档、动态生成图例后，颜色层次才回到数据本身。

N10｜但还缺视觉焦点。于是做 3D 重设计：柱高按贡献数的平方根编码，峰值日一百六十三次，长成全田唯一的孤峰。

N11｜相机是纯 Canvas 手写透视。焦距从一千零五十调到两千二，画面放大约一点四倍，透视反而更温和。

N12｜同一份数据有了三种读法：俯瞰读格子，等距读田垄，平视读天际线。

N13｜再往后是一架播种无人机：沿第一周到第五十三周掠过田垄，把有贡献的日子播回柱位，休耕地跳过。

N14｜全程约十秒，播下二百四十七枚、跳过一百二十三块；左半田已立起，右半仍是平面色块。

N15｜它没有另建数据，只复用「柱子是否长出」这个状态；任务换成巡检或收割，状态机也不必改。

N16｜之后的扩展让它从可看走向可操作：反事实编辑、六十秒纪录片、四种形态、生态层、年度海报。

N17｜抹掉一天，统计、田埂与四幕同步重算；实测去掉一天四十五次贡献，最长连续从三十七天变成二十一天。

N18｜同一份数据还能换成梯田、织物或年轮，共享相机与命中检测；想象层再热闹，也能一键退回数据视图。

N19｜最后是自定义账号：输入用户名或用户页链接，校验后经公开接口取回日历，规范化成相同结构，渲染层一行不用改。

N20｜格式错误、用户不存在、限流、通道全失败都有明确提示，且不会破坏当前正在看的数据。

N21｜克制同样重要：最初连续三天就画田埂，二十二条线把图表盖成线团；收紧到十二天和十天，叙事反而清楚。

N22｜五档色阶、悬停数值、统计卡与完整图例始终保留；页面也写明，贡献数不等于纯 commit 数。

N23｜说回 Hy4：六轮迭代都落在同一份单文件里，每轮先跑无头浏览器交互断言，再截图复核。

N24｜最后一轮，七十六项回归加三十七项账号断言全部通过，六十帧，零控制台报错。

N25｜最实在的体验是：改动能立刻被打开、被点击、被验证；长链路里数据结构不漂移，比一时炫目更有用。

N26｜这是一个零依赖的单文件网页，离线双击就能跑。先点从年初生长，再点起飞巡航，最后绕到平视看天际线。
